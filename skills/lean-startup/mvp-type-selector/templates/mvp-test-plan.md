# MVP Test Plan

Template for mvp-type-selector. Fill every bracket before launch. The threshold is
signed before the test runs and cannot be renegotiated after seeing results.

## Hypothesis

[One falsifiable sentence: "We believe [specific customer] will [specific behavior] when
[specific condition]."]

## Riskiest assumption

[The single assumption that, if false, ends this direction. Everything else can be
fixed; this one decides.]

## Test

- **MVP type:** [landing page / concierge / Wizard of Oz / piecemeal / single-feature /
  explainer video]
- **Why this type:** [one line tying the type to the riskiest assumption]
- **What it tests:** [learning outcome]
- **What it deliberately does not test:** [explicit non-goals]
- **Manual process behind the curtain (if concierge/WoZ):** [what you will do by hand,
  and the disclosure you owe users at conversion]

## Scope discipline

- Features that test the hypothesis: [list]
- Features cut from this version: [list — the longer this list, the better the test]

## Budget

- **Money:** [max spend]
- **Time:** [max person-days]
- **Clock:** the test ends on [date] regardless of results.

## Thresholds (signed before launch)

- **Pass:** [specific measurable result — e.g., "10% of 500 qualified visitors join the
  waitlist" — that means continue to the next loop]
- **Fail / kill:** [specific result that ends this direction or forces a pivot]
- **Gray zone:** [result that triggers one pre-planned follow-up test — named now, not
  improvised later]

## After the test

- If pass: [first thing to automate or build next, in order]
- If fail: [pivot or kill decision, and who makes it]
- If gray: [the pre-planned follow-up test]
- Learning log: what we believed before, what we saw, what we now believe.

## Rules

- Thresholds do not move after launch. A failed test that "felt close" is a failed test.
- Two hypotheses means two tests, sequenced — never in the same MVP.
- If the result would not change the next decision, the test was not worth running.
